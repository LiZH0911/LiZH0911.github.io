## 一、计算机系统概论

---

### 1.1 **冯·诺依曼结构与存储程序思想**

#### **1.1.1 冯·诺依曼结构**

冯·诺依曼机的**五大部件**：运算器、控制器、存储器、输入设备、输出设备。

- 控制器是“指挥中心”
- 运算器负责算术与逻辑运算
- 存储器存放程序和数据。

早期的冯·诺依曼机以运算器为中心，输入输出都要经过运算器。

![冯·诺依曼机的五大部件.png](images%2F%E5%86%AF%C2%B7%E8%AF%BA%E4%BE%9D%E6%9B%BC%E6%9C%BA%E7%9A%84%E4%BA%94%E5%A4%A7%E9%83%A8%E4%BB%B6.png)

现代计算机改为以存储器为中心，让 IO 设备直接与存储器交换数据。

- 控制器与运算器组成 CPU
- 存储器与 CPU 组成主机

![冯·诺依曼机的五大部件2.png](images%2F%E5%86%AF%C2%B7%E8%AF%BA%E4%BE%9D%E6%9B%BC%E6%9C%BA%E7%9A%84%E4%BA%94%E5%A4%A7%E9%83%A8%E4%BB%B62.png)

#### **1.1.2 冯·诺依曼结构的核心：存储程序思想**

**存储程序思想**：把程序和数据以二进制形式事先存入主存，计算机自动逐条取出指令并执行。不再需要人工插线干预。

CPU 靠时间阶段区分指令和数据：

1. 取指阶段：取出的是指令
2. 执行阶段：取出的是数据

**典型应用**：目前绝大多数计算机（PC、手机、服务器）都遵循冯·诺依曼结构，程序和数据统一存放在同一存储器中。

> 注意冯·诺依曼结构与哈佛结构（指令与数据分开存储）的区别。

---

### 1.2 **主存储器的基本组成：存储体、MAR、MDR**

主存储器（主存、内存）主要由**存储体、MAR（地址寄存器）、MDR（数据寄存器）**组成。

CPU 访问主存要借助 MAR 和 MDR 两个寄存器：

1. MAR 存放要访问的地址
    - MAR 位数 = 地址位数（可寻址空间），n 位 MAR 可寻址 \(2^n\) 个存储单元。n = 32 即 4G 个单元
2. MDR 存放读出或写入的数据
    - MDR 位数 = 存储字长（一个存储单元的位数），决定一次读写的数据位数。

![主存储器的基本组成.png](images%2F%E4%B8%BB%E5%AD%98%E5%82%A8%E5%99%A8%E7%9A%84%E5%9F%BA%E6%9C%AC%E7%BB%84%E6%88%90.png)

### 1.3 **计算机系统的层次结构、编译 vs 解释**

#### **1.3.1 计算机系统的层次结构**

- 硬件：硬件（硬联逻辑）、微程序机器 
- 软件：传统机器语言、操作系统、汇编语言、高级语言

![计算机系统的层次结构.png](images%2F%E8%AE%A1%E7%AE%97%E6%9C%BA%E7%B3%BB%E7%BB%9F%E7%9A%84%E5%B1%82%E6%AC%A1%E7%BB%93%E6%9E%84.png)

#### **1.3.2 编译 vs 解释**

- **编译**：把高级语言程序**整体**翻译成机器语言程序再执行（如 C/C++），执行速度快。
- **解释**：**逐条翻译、逐条执行**（如 Python/JavaScript 等脚本语言），灵活但速度慢。

![编译 vs 解释.png](images%2F%E7%BC%96%E8%AF%91%20vs%20%E8%A7%A3%E9%87%8A.png)

**易错提醒**：Java 是“先编译成字节码，再由 JVM 解释或即时编译（JIT）执行”，属于中间形态，常被考到。

### 1.4 **CPU 性能指标：机器字长、主频、CPI、MIPS、FLOPS**

#### **1.4.1 机器字长**

- **机器字长**： CPU 一次能处理的二进制位数（32/64 位），决定寄存器宽度与运算精度。通常等于通用寄存器与运算器的位数。

#### **1.4.2 时钟周期、主频**

- **时钟周期** T：CPU 中最小的时间单位
- **主频** f：时钟周期的倒数，单位为 Hz/GHz，决定每秒的时钟周期数。

![时钟周期与主频.png](images%2F%E6%97%B6%E9%92%9F%E5%91%A8%E6%9C%9F%E4%B8%8E%E4%B8%BB%E9%A2%91.png)

#### **1.4.3 CPI、执行时间、MIPS**

- **CPI（Cycles Per Instruction）**：执行一条指令平均所需的时钟周期数。受指令集的影响。

- **执行时间（CPU Time）**：程序实际运行所花的时间，是最直观的性能指标。

  $$
  \text{执行时间} = \text{指令条数} \times \text{CPI} \times \text{时钟周期}
  = \frac{\text{指令条数} \times \text{CPI}}{\text{主频}}
  $$

- **MIPS（Million Instructions Per Second）**：表示每秒执行的百万条指令数。

  $$
  \text{MIPS} = \frac{\text{主频}}{\text{CPI} \times 10^{6}}
  $$

**例题**：

某 CPU 主频 2GHz，执行 \(10^{8}\) 条指令、平均 CPI \(= 1.5\)，则执行时间 \(= 10^{8}\times 1.5\div (2\times 10^{9}) = 0.075\) 秒；MIPS \(= 2\times 10^{9}\div (1.5\times 10^{6})\approx 1333\)。

![CPI、执行时间、MIPS例题.png](images%2FCPI%E3%80%81%E6%89%A7%E8%A1%8C%E6%97%B6%E9%97%B4%E3%80%81MIPS%E4%BE%8B%E9%A2%98.png)

> 关键点：执行时间由三个因素共同决定——指令条数（IC）、CPI、时钟频率。单看其中任何一个都不能判断性能优劣。

![MIPS考点.png](images%2FMIPS%E8%80%83%E7%82%B9.png)

#### **1.4.4 吞吐量、响应时间、FLOPS**

- 吞吐量：单位时间内完成的任务/指令数
- 响应时间：从提交任务到完成的总时间
- FLOPS：每秒浮点运算次数，超级计算机的衡量标准

#### **1.4.5 三种字长对比**

| 指标 | 含义          | 考点要点 |
|------|-------------|----------|
| 机器字长 | CPU 一次处理的位数 | 决定运算精度、寄存器宽度 |
| 指令字长 | 一条指令的位数     | 定长便于取指译码，变长节省空间 |
| 存储字长 | 一个存储单元的位数   | 等于 MDR 位数 |


> 主频高不代表性能高，还要看 CPI；
> MIPS 不能跨指令集比较（不同指令复杂度不同）；
> 机器字长、指令字长、存储字长是三个不同概念。

## 二、数据的表示与运算

---

### 2.1 **进制转换**

- **二/八/十六进制相互转换**：三位二进制对应一位八进制，四位二进制对应一位十六进制。
- **二进制转十进制**：按权展开求和。
- **十进制转二进制**：整数部分除 2 取余，小数部分乘 2 取整。

**典型例题**

\((1011.01)_2 = 8 + 0 + 2 + 1 + 0 + 0.25 = (11.25)_{10}\)；十六进制 F 对应二进制 1111。

![小数进制转换.png](images%2F%E5%B0%8F%E6%95%B0%E8%BF%9B%E5%88%B6%E8%BD%AC%E6%8D%A2.png)

**易错提醒**

小数部分转二进制可能无限循环，要按题目要求保留位数；八进制/十六进制分组时要从小数点向两边分别分组。

---

### 2.2 **带符号整数：原码、反码、补码、移码**

- **原码**：符号位 + 绝对值；0 有两种表示（+0 与 -0）。
- **反码**：正数同原码；负数符号位不变、其余位取反；0 也有两种表示。
- **补码**：正数同原码；负数 = 反码 + 1；0 唯一表示；n 位补码范围 \(-2^{n-1} \sim 2^{n-1}-1\)。
    - 求补快捷法：从低位往高位找第一个 1，该位左边全部取反，右边保持不变。
- **移码**：补码的符号位取反，常用于浮点数阶码的表示。

> 正数的原码、反码、补码完全一样，区别全在负数上

![原码、反码、补码、移码.png](images%2F%E5%8E%9F%E7%A0%81%E3%80%81%E5%8F%8D%E7%A0%81%E3%80%81%E8%A1%A5%E7%A0%81%E3%80%81%E7%A7%BB%E7%A0%81.png)

**为什么普遍用补码？**

* 补码让加减法统一为加法
* 符号位直接参与运算
* 0 只有一种表示：00000000
* 多表示一个最小负数

---

### 2.3 **无符号数与有符号数的解释差异**

同一串二进制，按无符号解释和按有符号（补码）解释，得到的数值可能完全不同。

8 位二进制 11111111：按无符号数是 255；按 8 位补码是 -1。C 语言中 unsigned char 与 signed char 对同一字节的解释就不同。

> C 语言中有符号与无符号混合比较、类型转换（如 int 与 unsigned）时容易产生与直觉相反的结果。

---

### 2.4 **补码加减运算与溢出判断**

#### **2.4.1 补码加减运算**

- **补码加法**：直接相加，符号位也参与运算。
- **补码减法**：\(\mathrm{A - B = A + (-B)}\)，（-B）即对 B 取反加 1。

![补码加减运算.png](images%2F%E8%A1%A5%E7%A0%81%E5%8A%A0%E5%87%8F%E8%BF%90%E7%AE%97.png)

#### **2.4.2 溢出判断**

**溢出判断**三种方法：

1. **符号法**：两正数相加得负数、或两负数相加得正数，则溢出；
2. 进位法：最高位进位与次高位进位不同则溢出；
3. 双符号位法：结果符号位为 01 或 10 则溢出。

8 位补码 01111111（127）+ 00000001（1）= 10000000（-128），两正数得负数 \(\twoheadrightarrow\) 溢出。

> 无符号数没有“溢出”概念，只有“进位/借位”（CF）；有符号数才有溢出（OF）。

---

### 2.5 **标志位 ZF/SF/OF/CF**

标志位是 CPU 运算后自动留下的“便签”，告诉后续指令刚才发生了什么。

| 标志位 | 名称 | 置 1 条件 |
|--------|------|-----------|
| ZF | 零标志 | 运算结果为 0 |
| SF | 符号标志 | 运算结果为负 |
| OF | 溢出标志 | **有符号**运算溢出 |
| CF | 进位/借位标志 | **无符号**运算最高位进位/借位 |

![OF、CF.png](images%2FOF%E3%80%81CF.png)

> CMP 指令不保存结果，只影响标志位。

条件转移指令（JZ/JNZ/JE/JNE 等）根据标志位决定是否跳转；比较两个数常用减法只改标志位。

---

### 2.6 **全加器、串行进位、先行进位、ALU**

- **全加器**：完成一位二进制加法，考虑低位进位输入。
- **串行进位加法器**：进位逐位传递，电路简单但速度慢。
- **先行进位（CLA）**：并行产生进位，速度快。
- **算术逻辑单元（ALU）**：加法器 + 逻辑运算电路，支持加、减、与、或、非、移位等运算。

![加法器.png](images%2F%E5%8A%A0%E6%B3%95%E5%99%A8.png)

![先行进位.png](images%2F%E5%85%88%E8%A1%8C%E8%BF%9B%E4%BD%8D.png)

串行进位像排队一个个传纸条（进位链太长），先行进位像广播通知所有人，后者明显更快。

现代 CPU 的 ALU 内部使用先行进位加法器以提高加法速度。

---

### 2.7 **移位运算：逻辑移位与算术移位**

移位是“移动小数点”的二进制版本，硬件实现非常快。

- **逻辑移位（无符号）**：
    - 左移、右移空出的位都补 0。
- **算术移位（补码）**：
    - 左移：低位补 0。左移可能把符号位移丢导致溢出。
    - 右移：高位补符号位（保持符号）

左移一位相当于乘 2，右移一位相当于除 2（算术右移对负数向下取整）。

C 语言中 \(>>\) 对 unsigned 是逻辑右移、对 signed 是算术右移；编译器常用移位代替乘除 2 的幂。

---

### 2.8 **位数扩展：符号扩展与零扩展**

- **符号扩展**（有符号）：高位补符号位，数值不变。
- **零扩展**（无符号）：高位补 0，数值不变。

8 位 -1（11111111）符号扩展为 16 位 → 1111111111111111；C 语言中 char 转 int、short 转 int 自动进行符号扩展。

int 转 short 是截断高位而不是符号扩展，可能改变数值甚至符号。

---

### 2.9 **乘法实现思想**

**乘法实现思想**：“移位 + 加法”，逐位乘积累加。手工竖式乘法就是该思想的直观体现，计算机硬件把它自动化。

**乘积的位数** = 两操作数位数之和，需要双倍宽度寄存器或分步处理。

\(1101 \times 1011\)，从低位到高位逐位看乘数，是 1 就加上被乘数并左移一位，最后求和。

![乘法.png](images%2F%E4%B9%98%E6%B3%95.png)

---

### 2.10 **浮点数与 IEEE 754 标准**

#### **2.10.1 浮点数：解决定点数的表示范围问题**

- **定点数**：小数点位置固定，表示范围小、精度固定。
- **浮点数**：类似科学计数法。阶码管“2 的几次方”，尾数管“几位有效数字”。
    - **阶码 E**：整数部分，决定范围。
    - **尾数 M**：小数部分，决定精度。为了让精度最高，通常要求尾数的最高有效位是 1（规格化，最高位 1 可不存）。

![浮点数.png](images%2F%E6%B5%AE%E7%82%B9%E6%95%B0.png)

#### **2.10.2 IEEE 754 标准**

- 单精度 float（32 位）= 1 位符号 S + 8 位阶码 E + 23 位尾数 M，偏置值 127。
- 双精度 double（64 位）= 1 + 11 + 52，偏置值 1023。
- 规格化数：尾数最高位隐藏为 1（隐藏位），实际尾数为 1.M。

![单精度 float（32 位）.png](images%2F%E5%8D%95%E7%B2%BE%E5%BA%A6%20float%EF%BC%8832%20%E4%BD%8D%EF%BC%89.png)

**例题**：

把 12.5 转为 IEEE754 单精度。\(12.5 = 1100.1_2 = 1.1001\times 2^{3}\)；\(S = 0\)；

阶码 \(E = 3 + 127 = 130 = 10000010\)；尾数 \(M = 1001000\dots 0\)（23 位）。

![单精度 float（32 位）例题.png](images%2F%E5%8D%95%E7%B2%BE%E5%BA%A6%20float%EF%BC%8832%20%E4%BD%8D%EF%BC%89%E4%BE%8B%E9%A2%98.png)

**阶码全 0/1 的特殊值**：

- 阶码全 0：表示非规格化数或 0；
- 阶码全 1：表示无穷大或 NaN。

![阶码全0或全1的特殊值.png](images%2F%E9%98%B6%E7%A0%81%E5%85%A80%E6%88%96%E5%85%A81%E7%9A%84%E7%89%B9%E6%AE%8A%E5%80%BC.png)

- float 最大正数约 \(3.4\times 10^{38}\)，最小正规格化数约 \(1.2\times 10^{-38}\)。
- float 只有 24 位有效二进制位，int 转 float 可能丢失精度；
- 0.1 在二进制中无法精确表示，不能用 \(==\) 直接判断浮点相等。

![float 最大正数.png](images%2Ffloat%20%E6%9C%80%E5%A4%A7%E6%AD%A3%E6%95%B0.png)

---

### 2.11 **浮点数加减运算**

**步骤**：

1. **对阶**：小阶向大阶看齐，阶码小的尾数右移相应位数。
2. **尾数加减**：按补码/原码规则对尾数进行加减。
3. **规格化**：调整尾数与阶码，使尾数落在规格化范围。
4. **舍入**：丢弃低位时采用就近舍入等规则。
5. **溢出判断**：阶码超出表示范围则上溢或下溢。

![浮点数加减五步.png](images%2F%E6%B5%AE%E7%82%B9%E6%95%B0%E5%8A%A0%E5%87%8F%E4%BA%94%E6%AD%A5.png)

> 对阶就像“对齐小数点”，必须让两个数的 10 的幂一致才能加减。
> 
> 对阶时小阶的尾数右移会丢失低位精度，误差极小
> 
> 溢出判断看的是阶码而不是尾数。

---

### 2.12 **大端与小端、边界对齐**

#### **2.12.1 大端与小端**

- **大端**：高位字节存低地址；
- **小端**：低位字节存低地址。
- x86 处理器是小端；网络协议通常规定大端字节序。

![大端与小端.png](images%2F%E5%A4%A7%E7%AB%AF%E4%B8%8E%E5%B0%8F%E7%AB%AF.png)

> 大端小端就是“从哪头开始放字节”——像写数字是从左到右还是从右到左。
> 
> 例如 32 位整数 0x12345678 在小端机内存中按 78563412 顺序存放。
> 
> 大端小端针对“字节顺序”而非“位顺序”；跨平台传输数据时要注意字节序转换。

#### **2.12.2 边界对齐**

- **边界对齐**：多字节数据的起始地址按自身长度对齐（如 4 字节数据地址为 4 的倍数），可提高访存效率。

![边界对齐.png](images%2F%E8%BE%B9%E7%95%8C%E5%AF%B9%E9%BD%90.png)

## 三、存储系统

---

### 3.1 **存储器的层次结构**

- 存储器层次：寄存器 \(\rightarrow\) Cache \(\rightarrow\) 主存 \(\rightarrow\) 辅存（外存）。
    - Cache —— 主存层次：解决“**速度**”问题，由硬件自动完成，对程序员透明。
    - 主存 —— 辅存层次：解决“**容量**”问题，即**虚拟存储**，由操作系统与硬件共同完成。
- 层次化思想：用小而快的存储加上大而慢的存储，换来又快又大的整体效果。

![存储器的层次结构.png](images%2F%E5%AD%98%E5%82%A8%E5%99%A8%E7%9A%84%E5%B1%82%E6%AC%A1%E7%BB%93%E6%9E%84.png)

CPU 中的 Cache、主存中的页表、磁盘上的交换文件，构成完整存储体系。

---

### 3.2 **存储器分类与性能指标**

#### **3.2.1 存储器分类：按存取方式**

| 类型        | 特点 | 典型用途            |
|-----------|------|-----------------|
| **RAM**（随机存取） | 可读可写，断电丢失（易失），访问时间与位置无关 | 主存、Cache        |
| **ROM**（只读）   | 非易失，内容固定 | 固件、引导程序         |
| SAM（顺序存取） | 按物理顺序寻找，时间与位置有关 | 磁带              |
| DAM（直接存取） | 先直接定位到区域再顺序查找 | 磁盘（先找到磁道再顺序找扇区） |

#### **3.2.2 存储器分类：按信息的可保存性**

- **易失性**：断电后数据会丢失，如 RAM。
- **非易失性**：断电后数据不会丢失，如 ROM、磁盘、闪存。

#### **3.2.3 主存的性能指标**

- **存储容量** \(=\) 存储单元个数 \(\times\) 存储字长。
- **存取时间**：启动一次存取所需的时间。
- **存取周期**：连续两次存取的最短时间间隔（**含恢复时间**）。

![主存的性能指标.png](images%2F%E4%B8%BB%E5%AD%98%E7%9A%84%E6%80%A7%E8%83%BD%E6%8C%87%E6%A0%87.png)

### 3.3 **RAM：SRAM、DRAM**

#### **3.3.1 SRAM 与 DRAM 对比**

| 对比项    | SRAM（静态）    | DRAM（动态） |
|--------|-------------|----------|
| 存储原理   | 双稳态触发器      | 电容存储电荷   |
| 速度     | 快           | 较慢       |
| 集成度 | 低           | 高        |
| 功耗/价格  | 大/高         | 小/便宜     |
| 是否刷新   | 不需要         | 必须定期刷新   |
| 用途     | CPU 的 Cache | 主存（内存条）  |

> SRAM 不需要刷新，DRAM 必须刷新；
> 
> 刷新本质是“读后重写”防止电容漏电，不是重新写入数据。

#### **3.3.2 DRAM 的刷新**

三种方式：

* 集中刷新：刷新期间停止访问，有“死区”
* 分散刷新：无死区但速度慢
* **异步刷新**：折中，常用

![DRAM 的刷新.png](images%2FDRAM%20%E7%9A%84%E5%88%B7%E6%96%B0.png)

* DRAM 地址分“行、列”两次送入芯片，地址引脚数可减半。
* 刷新由存储器自己完成，不需要 CPU 参与

![DRAM考点.png](images%2FDRAM%E8%80%83%E7%82%B9.png)

### 3.4 **ROM 系列与 Flash**

- ROM 系列：掩膜 ROM（出厂固定）、PROM（一次可编程）、EPROM（紫外擦除重写）、EEPROM（电擦除重写）。
- Flash 闪存：电可擦写、非易失，U 盘、SSD 的存储介质。
    - Flash 以页为单位读写、以块为单位擦除，写之前必须先擦除。

![ROM的发展.png](images%2FROM%E7%9A%84%E5%8F%91%E5%B1%95.png)

* BIOS 固件存 ROM；
* 手机、U 盘、SSD 用 Flash 存储。

> ROM 不是“完全不能写”，PROM/EPROM/EEPROM 都可写，只是写入方式不同；Flash 写入前必须先擦除。

### 3.5 **存储器扩展：位扩展、字扩展、字位同时扩展**

#### **3.5.1 位扩展、字扩展、字位同时扩展**

- **位扩展**：增加字长，各芯片数据线并联到不同位（\(2\mathrm{K}\times 4\) 两片 \(\rightarrow 2\mathrm{K}\times 8\)）。

![位扩展.png](images%2F%E4%BD%8D%E6%89%A9%E5%B1%95.png)

- **字扩展**：增加单元数，片选信号区分不同芯片（\(2\mathrm{K}\times 8\) 四片 \(\rightarrow 8\mathrm{K}\times 8\)）。
- **字位同时扩展**：既增字长又增单元数（\(2\mathrm{K}\times 4\rightarrow 8\mathrm{K}\times 8\) 需要 8 片）。

用 \(2\mathrm{K}\times 4\) 位芯片组成 \(8\mathrm{K}\times 8\) 位存储器：每组 2 片做位扩展（4 位 \(\rightarrow 8\) 位），共 4 组做字扩展（\(2\mathrm{K}\rightarrow 8\mathrm{K}\)），总片数 \(= 2\times 4 = 8\) 片。

![字扩展.png](images%2F%E5%AD%97%E6%89%A9%E5%B1%95.png)

![各组的地址范围.png](images%2F%E5%90%84%E7%BB%84%E7%9A%84%E5%9C%B0%E5%9D%80%E8%8C%83%E5%9B%B4.png)

#### **3.5.2 片选方法**

- 片选方法：线选法（一根高位地址线选一片，简单但地址不连续、浪费空间）；译码片选法（译码器译码，地址连续，最常用）。
- 片内地址线根数 \(=\) log2（芯片字数）；剩余高位地址线用于片选。

![片选方法.png](images%2F%E7%89%87%E9%80%89%E6%96%B9%E6%B3%95.png)

> 片数 \(=\) （目标字数 \(\div\) 芯片字数） \(\times\) （目标字长 \(\div\) 芯片字长）；线选法地址不连续，考题常考与译码片选的对比。

### 3.6 **多模块存储器与双端口 RAM**

光扩大容量不够，还要提高速度。

#### **3.6.1 多模块存储器**

- **高位交叉编址**：高位地址选体，连续地址在同一存储体内，只能扩充容量，不能提高连续访问速度。

![高位交叉编址.png](images%2F%E9%AB%98%E4%BD%8D%E4%BA%A4%E5%8F%89%E7%BC%96%E5%9D%80.png)

- **低位交叉编址**：低位地址选体（体号 \(=\) 地址 mod 体数），连续地址分布在不同存储体，可流水式并行访问，提高带宽。

![低位交叉编址.png](images%2F%E4%BD%8E%E4%BD%8D%E4%BA%A4%E5%8F%89%E7%BC%96%E5%9D%80.png)

- 连续读 M 个字的时间 \(= \mathrm{T} + (\mathrm{M} - 1)\times \mathrm{r}\)（T 为存取周期，r 为总线传送周期）；
- 为实现流水线式访问（不等待），体数 \(M\geq T / r\)。

**例题**：4 个体、存取周期 \(\mathrm{T} = 200\mathrm{ns}\)、总线传送 \(\mathrm{r} = 50\mathrm{ns}\)，低位交叉连续读 4 个字用时 \(200 + 3\times 50 = 350\mathrm{ns}\)；若不交叉顺序访问需 \(4\times 200 = 800\mathrm{ns}\)。

![低位交叉.png](images%2F%E4%BD%8E%E4%BD%8D%E4%BA%A4%E5%8F%89.png)

> 只有“低位交叉”才能连续读提速，“高位交叉”主要扩充容量；体数不足 T/r 时连续读要等待。

- **双端口 RAM**：两组独立端口，可同时访问不同单元；**同时访问同一单元才发生冲突**。

### 3.7 **Cache 基础**

#### **3.7.1 Cache 介绍**

**Cache** 位于 CPU 与主存之间，容量小、速度快，用 SRAM 实现。

* Cache 和主存都被划分为大小相同的块，Cache 中的块也叫 Cache 行。
* CPU 访问数据时先查 Cache，找到了叫**命中**，直接读；没找到叫缺失，就把主存中的整块数据调进 Cache，下次再访问同一块数据就命中。

> Cache 像“办公桌上的常用文件”，大部分请求都在桌上解决，少数才去文件柜（主存）取。

#### **3.7.2 局部性原理**

- **局部性原理**：时间局部性（刚访问的数据很快再次访问，如循环变量）；空间局部性（附近数据很快被访问，如顺序遍历数组）。

> 二维数组按行遍历比按列遍历快（空间局部性）。

#### **3.7.3 命中率和平均访问时间**

- **命中率** \(H =\) 命中次数 \(\div\) 总访问次数；缺失率 \(= 1 - H\)。
- **平均访问时间**：
    - 同时访问：\(H\times tc + (1 - H)\times tm\)；
    - 先访问 Cache，不命中再访问主存：\(H\times tc + (1 - H)\times (tc + tm)\)。

> “先访问 Cache”与“同时访问”的平均时间公式不同（缺失时一个要加 tc，一个不加）；

**例题**：访问 2000 次，Cache 命中 1900 次，则命中率为

\[
H = \frac{1900}{2000} = 0.95
\]

已知 \(t_c = 50\,\mathrm{ns}\)，\(t_m = 250\,\mathrm{ns}\)，则同时访问时的平均访问时间为

\[
0.95 \times 50 + 0.05 \times 250 = 60\,\mathrm{ns}
\]

### 3.9 **Cache 替换算法**

Cache 满了，新块如何替换旧块？

* 直接映射：位置固定，没得选
* 全相联/组相联映射：需要替换算法

**常见替换算法**：

- 随机替换 **RAND**：任意选一行淘汰。
- **FIFO**：先进先出，淘汰最早进入的行。
- **LRU**：近期最少使用，淘汰最久未访问的行，**最符合局部性原理**，命中率通常更高。
    - LRU 给每行配一个计数器（替换控制位），**每行位数 = log₂（路数）**：2 路组相联每行 1 位，4 路每行 2 位。
- **LFU**：最不经常使用，淘汰访问次数最少的行。

![常见 Cache 替换算法.png](images%2F%E5%B8%B8%E8%A7%81%20Cache%20%E6%9B%BF%E6%8D%A2%E7%AE%97%E6%B3%95.png)

### 3.10 **Cache 写策略与总容量计算**

#### **3.10.1 Cache 写策略**

- **全写法**（写直通）：写 Cache 的同时写主存
    - 优点：一致性好
    - 缺点：**每次写都访问慢速主存**
    - 解决方法：可加写缓冲。
- **写回法**：只写 Cache，被替换出去时才写回主存，需“脏位”
    - 优点：减少访存次数
    - 缺点：主存与 Cache 暂时不一致。

> 写直达像“每记一笔都同步到账本”，写回像“先记草稿、下班再统一誊写”。

- 写不命中时的做法：
    - **写分配**：先把块调入 Cache 再写，通常搭配写回法；
    - **非写分配**：直接写主存，不调块，通常配全写法。

#### **3.10.2 Cache 总容量计算**

- Cache 总容量 = 每行（有效位 1 + 脏位 1 + LRU 位 + tag + 数据块）× 行数。

> 算 Cache 总容量必须包含有效位、脏位、LRU 位、标记位，不能只算数据区大小。

**例题**（直接映射、写回法，无替换位）：每行数据 512 位、tag 17 位

每行 = 1（有效） + 1（脏） + 17（tag） + 512 = 531 位；

512 行总容量 = 512 × 531 位。

![Cache 总容量计算.png](images%2FCache%20%E6%80%BB%E5%AE%B9%E9%87%8F%E8%AE%A1%E7%AE%97.png)

### 3.11 **多级 Cache 与虚拟存储器（TLB）**

#### **3.11.1 多级 Cache**

现代 CPU 采用**多级 Cache**：L1 最快且分指令 Cache 与数据 Cache；L2/L3 容量更大，指令数据混合。

![多级 Cache.png](images%2F%E5%A4%9A%E7%BA%A7%20Cache.png)

#### **3.11.2 虚拟存储器（TLB）**

**虚拟存储器（TLB）**即操作系统课里的分页机制。

- CPU 发出虚拟地址 \(\rightarrow\) 查 TLB（快表） \(\rightarrow\) 命中得物理地址；
- TLB 未命中再查主存页表。

现代 CPU 的地址转换过程：虚拟地址 \(\rightarrow\) TLB \(\rightarrow\) 物理地址 \(\rightarrow\) Cache 命中判断 \(\rightarrow\) 取数据。

![完整的访存路径.png](images%2F%E5%AE%8C%E6%95%B4%E7%9A%84%E8%AE%BF%E5%AD%98%E8%B7%AF%E5%BE%84.png)

#### **3.11.3 TLB、页表、Cache的命中组合**

组合题两条规则：

1. TLB 命中 \(\rightarrow\) 页表一定命中（TLB 是页表的缓存）；
2. 页表缺页 \(\rightarrow\) 数据不在主存 \(\rightarrow\) Cache 一定不命中（Cache 是主存的缓存）。

![TLB、页表、Cache组合可能.png](images%2FTLB%E3%80%81%E9%A1%B5%E8%A1%A8%E3%80%81Cache%E7%BB%84%E5%90%88%E5%8F%AF%E8%83%BD.png)

> TLB 是页表的“Cache”，查完页表才能拿到物理地址，再判断 Cache 是否命中。

## 四、指令系统

---

### 4.1 **指令与指令系统**

- **指令**：让计算机完成某种操作的命令
- **指令系统（指令集）**：一台计算机所有指令的集合，是软件与硬件之间的接口。
- 一条指令 = **操作码 OP**（做什么）+ **地址码 A**（操作数在哪、结果放哪）。
    - **指令字长**可以是定长（便于取指与译码）或变长（节省存储空间）。
    - **操作码的长度**也一样，可定长，也可采用扩展操作码

> x86 用变长指令节省空间，ARM/RISC-V 用定长指令简化硬件。
> 
> 指令字长与机器字长是两个概念：指令字长由指令格式决定，机器字长由 CPU 处理能力决定。

---

### 4.2 **按地址码个数分类**

| 类型 | 格式 | 说明 | 访存次数 |
|------|------|------|----------|
| 三地址 | OP A1 A2 A3 | A1 与 A2 运算，结果存 A3 | 取指 1 + 两操作数 2 + 存结果 1 = 4 |
| 二地址 | OP A1 A2 | A1 与 A2 运算，结果覆盖 A1 | 取指 1 + 两操作数 2 + 存结果 1 = 4（寄存器时可少） |

![指令按地址码个数分类.png](images%2F%E6%8C%87%E4%BB%A4%E6%8C%89%E5%9C%B0%E5%9D%80%E7%A0%81%E4%B8%AA%E6%95%B0%E5%88%86%E7%B1%BB.png)


地址码越多，一条指令能表达的操作越完整，但指令越长、访存越多。

堆栈计算机常用零地址指令（弹两个数相加压回）；汇编中 MOV 多为二地址。

#### **4.2.4 易错提醒**

二地址指令的结果覆盖 A1（原内容丢失）；三地址指令访存 4 次是最多的。

---

### 4.3 **定长操作码与扩展操作码**

- **定长操作码**：所有指令操作码位数相同，译码简单但条数受限。
- **扩展操作码**：短操作码指令留出若干编码作为“扩展窗口”，把操作码向地址码方向延伸。
    - 原则：**短操作码不能是长操作码的前缀**（避免译码歧义）。
    - 计算套路：上一级留下 K 个编码作扩展，下一级最多有 \(\mathrm{K} \times 2^{\mathrm{A}}\)（扩展位数）条指令。

**例题 1**：

**指令格式**：16 位指令字长，由 \(4\) 位操作码 + \(3\) 个 \(4\) 位地址码组成。

操作码采用扩展方式，各指令数量计算如下：

* **三地址指令**：基础操作码为 `0000` ～ `1110`，共 **15 条**；
* **二地址指令**：保留 `1111` 作为扩展标志，与下一个 \(4\) 位组合（即 `1111 0000` ～ `1111 1110`），共 **15 条**；
* **一地址指令**：保留 `1111 1111` 继续扩展，再加下一个 \(4\) 位组合（即 `1111 1111 0000` ～ `1111 1111 1110`），共 **15 条**；
* **零地址指令**：保留 `1111 1111 1111` 继续扩展最后 \(4\) 位（即 `1111 1111 1111 0000` ～ `1111 1111 1111 1111`），共 **16 条**。

![扩展操作码.png](images%2F%E6%89%A9%E5%B1%95%E6%93%8D%E4%BD%9C%E7%A0%81.png)

**例题 2**：三地址指令使用了 12 条，剩余 4 个编码可作为扩展窗口（即 2 位扩展标志位），则二地址指令最多有：

\[
4 \times 16 = 64 \text{ 条}
\]

---

### 4.4 **指令功能分类**

#### **4.4.1 定义/要点**

- 数据传送：MOV 类指令，在寄存器、存储单元、立即数之间搬数据。
- 算术逻辑运算：ADD、SUB、MUL、DIV、AND、OR、XOR 等。
- 移位指令：逻辑移位、算术移位、循环移位。
- 转移类：无条件转移 JMP；条件转移 Jcc（根据标志位决定是否跳转）。
- 过程调用 CALL 与返回 RET；输入输出指令。
- 比较两个数（CMP）= 做减法，只设置标志位、不保存结果。

#### **4.4.2 直观理解**

指令集像“工具箱”，不同工具完成不同任务。

#### **4.4.3 典型应用（代码示例）**

```
CMP EAX, EBX ；比较 EAX 与 EBX，只影响标志位
JE label ；相等则跳转（ZF=1）
JMP label ；无条件跳转
CALL sub ；过程调用
RET ；返回
```

#### **4.4.4 易错提醒**

CMP 不保存差值只影响标志位；条件转移依赖 ZF/SF/OF/CF 等标志。

---

### 4.5 **寻址方式总览**

#### **4.5.1 定义/要点**

- 指令寻址：顺序寻址（PC+1）与跳跃寻址（转移指令把目标地址送 PC）。
- 数据寻址：确定操作数的有效地址 EA。
- 记忆环境（例题默认）：指令地址码 A=200；主存 200 号单元存 300，300 号单元存 700，1000 号单元存 900；寄存器 R1=300，变址寄存器 IX=1000。

| 寻址方式 | 有效地址/操作数 | 访存次数 | 特点 |
|----------|----------------|----------|------|
| 立即寻址 | 操作数 = 指令中的常数 200 | 0 | 最快，数值范围受限 |
| 直接寻址 | EA = A = 200，操作数 = 300 | 1 | 简单直观 |

#### **4.5.2 直观理解**

寻址方式就是“告诉 CPU 去哪里找操作数”的不同说法——写在指令里、直接去内存、绕道去问别人。

#### **4.5.3 典型应用（口诀）**

访存次数——立即、寄存器 0 次；直接、寄存器间接、相对、基址、变址 1 次；间接 2 次。基址归操作系统，变址归用户。

#### **4.5.4 典型应用（相对寻址例题）**

两字节相对转移指令位于 2000H，偏移量 06H，取指后 \(\mathrm{PC} = 2002\mathrm{H}\)，目标 \(= 2002 + 06 = 2008\mathrm{H}\)。

#### **4.5.5 易错提醒**

相对寻址的 PC 是“取出指令后已更新”的值，不是当前指令地址；间接寻址访存 2 次最慢。

---

### 4.6 **x86 寻址示例**

#### **4.6.1 典型应用（代码示例）**

```
MOV EAX, 5 ; 立即寻址：把常数 5 送入 EAX
MOV EAX, EBX ; 寄存器寻址：EBX 内容送 EAX
MOV EAX, [EBX] ; 寄存器间接寻址：EA = EBX 内容
MOV EAX, [EBX+ESI*4+8] ; 基址+变址+偏移：访问数组元素
```


#### **4.6.2 直观理解**

方括号表示“去内存取值”，括号内是地址计算式，等价于基址寻址加变址寻址的组合。

#### **4.6.3 易错提醒**

没有方括号的是寄存器寻址（取寄存器内容），带方括号的是寄存器间接寻址（取内存），写法不同含义不同。

---

### 4.7 **CISC 与 RISC**

#### **4.7.1 定义/要点**

| 对比项 | CISC | RISC |
|--------|------|------|
| 指令 | 多而复杂、长度可变 | 少而规整、定长 |
| 寻址方式 | 丰富 | 简单，只有 load/store 访存 |
| 寄存器 | 较少 | 较多 |
| 控制方式 | 多用微程序控制 | 多用硬布线控制 |
| 流水线 | 不太适合 | 非常适合 |
| 代表 | x86 | ARM、RISC-V |

RISC 的出发点之一是“二八定律”：程序中 \(80\%\) 的时间在反复执行 \(20\%\) 的简单指令，所以把常用简单指令做快。

#### **4.7.2 直观理解**

CISC 像“多功能瑞士军刀”，RISC 像“一套标准螺丝刀”，后者更利于流水线批量生产。

#### **4.7.3 典型应用**

手机处理器多基于 ARM（RISC）；PC 多用 x86（CISC，内部可微码翻译）。

#### **4.7.4 易错提醒**

RISC 不是“指令少到只有几条”，而是“规整、精简、便于流水线”；只有 load/store 两条指令能访问内存。

---


## 五、中央处理器（CPU）

---

### 5.1 **CPU 的功能与组成**

#### **5.1.1 定义/要点**

- CPU 五大功能：指令控制、操作控制、时间控制、数据加工、中断处理。
- 运算器组成：ALU（核心） + 累加器 ACC + 通用寄存器组 + 暂存寄存器 + 程序状态字 PSW。
- 控制器组成：PC（下一条指令地址）、IR（当前指令）、指令译码器、时序系统与微操作信号发生器、MAR/MDR。
- 程序员可见寄存器：PC、通用寄存器、PSW（汇编可直接访问）；不可见：IR、MAR、MDR、暂存寄存器。

#### **5.1.2 直观理解**

CPU 像“车间主任 + 工人”：控制器发号施令，运算器动手干活。

#### **5.1.3 典型应用**

汇编程序员能直接读写 PC、通用寄存器、标志寄存器（PSW），但看不到 IR、MAR、MDR。

#### **5.1.4 易错提醒**

IR 存放“正在执行”的指令，PC 存放“下一条”指令地址；MAR/MDR 对程序员透明。

---

### 5.2 **指令周期与取指周期**

#### **5.2.1 定义/要点**

- 指令周期 \(=\) 取指周期 \(+\)（间指周期）\(+\) 执行周期 \(+\)（中断周期）。
- 取指、执行：每条指令必有；间指周期：仅间接寻址才有；中断周期：仅中断请求且允许中断时才有。
- 取指周期微操作序列：PC \(\twoheadrightarrow\) MAR \(\twoheadrightarrow\) 主存读出 \(\rightarrow\) MDR \(\twoheadrightarrow\) MDR \(\twoheadrightarrow\) IR \(\twoheadrightarrow\) PC+1（可与访存同时进行）\(\twoheadrightarrow\) 操作码送译码器。
- 间指周期：把地址码送 MAR \(\twoheadrightarrow\) 主存读出有效地址 \(\twoheadrightarrow\) 放回地址码字段。

#### **5.2.2 直观理解**

指令周期像“上课流程”：点名（取指）、提问（间指）、讲课（执行）、课间（中断）。

#### **5.2.3 典型应用**

判断一条指令的周期数，先看是否间接寻址、执行期间是否可能响应中断。

#### **5.2.4 易错提醒**

PC+1 在取指过程中完成，可与访存并行；相对寻址计算中用到的 PC 是“更新后”的值。

---

### 5.3 **数据通路**

#### **5.3.1 定义/要点**

- 单总线结构：所有寄存器与 ALU 都挂在一条内部总线上，同一时刻只能传一个数据。
- 需要暂存器 Y（ALU 的一个输入）和 Z（ALU 输出），因为总线一次只能传一个数，而 ALU 有两个输入。
- 例 ADD R0,R1（结果存回 R0）：① R0out, Yin；② R1out, ALU 加法 \(\rightarrow\) Z；③ Zout, R0in。
- 专用数据通路：速度快但硬件量大；单总线：结构简单但冲突多、速度慢。

#### **5.3.2 直观理解**

单总线像“单车道桥”，一次只能过一辆车，所以要先停在 Y 再进 ALU，结果先存在 Z。

#### **5.3.3 典型应用**

许多教学机（如单总线 CPU）用 Y/Z 暂存器实现运算三步走。

#### **5.3.4 易错提醒**

单总线结构下 ALU 的两个输入不能同时来自总线，必须用暂存器 Y 缓冲其中一个。

---

### 5.4 **硬布线控制器与微程序控制器**

#### **5.4.1 定义/要点**

| 对比项 | 硬布线 | 微程序 |
|--------|--------|--------|
| 原理 | 组合逻辑电路直接产生控制信号 | 把微操作编成微程序存于控制存储器 CM（ROM） |
| 速度 | 快 | 较慢（要读微指令） |
| 灵活性 | 难修改、电路复杂 | 规整、灵活、易修改 |
| 适用 | RISC | CISC |

层级关系——一条机器指令 \(\oplus\) 一段微程序 \(\oplus\) 若干微指令 \(\oplus\) 若干微命令（控制信号）/微操作（动作）。

#### **5.4.2 直观理解**

硬布线像“固定线路的电路板”，微程序像“把控制流程写成小程序存进 ROM”。

#### **5.4.3 典型应用**

x86 复杂指令多用微程序实现，ARM 等 RISC 多用硬布线。

#### **5.4.4 易错提醒**

微程序控制器慢于硬布线，但便于修改与扩展；控制存储器 CM 是 ROM，属于 CPU 内部。

---

### 5.5 **微指令格式与微命令编码**

#### **5.5.1 定义/要点**

- 水平型微指令：一条可并行发出多个微命令，字长较长，执行快。
- 垂直型微指令：像普通机器指令带操作码，一条完成一两个微操作，字长短但慢。
- 微命令编码：直接编码（每位对应一个微命令，直观但位数多）；字段直接编码（把互斥微命令分到同一字段编码，字段要留一个“什么都不做”的编码）。
- 公式：K 个互斥微命令需要 \(\lceil \log_2 (K+1) \rceil\) 位。

#### **5.5.2 直观理解**

水平型像“一句话布置多项任务”，垂直型像“一条命令只做一件事”。

#### **5.5.3 典型应用（例题）**

四组互斥微命令个数分别为 7、3、2、4：字段直接编码需要 \(3 + 2 + 2 + 3 = 10\) 位；直接编码则需要 \(7 + 3 + 2 + 4 = 16\) 位，字段编码首位。

#### **5.5.4 易错提醒**

字段编码必须给“空操作”留一个编码，所以 K 个微命令按 K+1 取对数；互斥的才放同一字段。

---

### 5.6 **指令流水线**

#### **5.6.1 定义/要点**

- 经典五段流水线：取指 IF \(\rightarrow\) 译码 ID \(\rightarrow\) 执行/计算地址 EX \(\rightarrow\) 访存 MEM \(\rightarrow\) 写回 WB。
- 时空图：横轴为时间、纵轴为指令，相邻指令错开一段进入。
- 总时间 \(= (K + N - 1)\times \Delta t\)（K 段、N 条指令、每段 \(\Delta t\)）。
- 吞吐率 \(= N\div\) 总时间；加速比 \(= N\times K\times \Delta t\div\) 总时间；效率 \(=\) 时空图中占用格子数 \(\div\) 总格子数。
- \(N\rightarrow \infty\) 时：加速比趋近段数 K，CPI 趋近 1。

#### **5.6.2 直观理解**

流水线像“工厂流水线”——第一件产品还没做完，第二件已经开工，单位时间产出更多。

#### **5.6.3 典型应用（例题）**

5 段流水线、每段 10ns、执行 10 条指令：总时间 \(= 14\times 10 = 140\mathrm{ns}\)；吞吐率 \(\approx 7.14\times 10^{4}\) 条/秒；加速比 \(= 500 / 140\approx 3.57\)；效率 \(\approx 10 / 14\approx 71\%\)。

#### **5.6.4 典型应用（各段时间不等）**

五段时间 8/5/10/7/6 皮秒 \(\twoheadrightarrow\) 时钟周期取最慢段 10ps，成为瓶颈。

#### **5.6.5 易错提醒**

流水线不能缩短单条指令的执行时间（反而因迁就最慢段和段间寄存器可能更慢），提高的是吞吐率；各段时间不等时周期取最慢段。

---

### 5.7 **流水线冒险**

#### **5.7.1 定义/要点**

| 冒险类型 | 成因 | 典型解决 |
|----------|------|----------|
| 结构冒险 | 硬件资源冲突（取指与访存抢存储器） | 指令 Cache 与数据 Cache 分离 |
| 数据冒险 | 后续指令要用前面结果但未写回（RAW 写后读） | 插入气泡停顿；数据旁路/转发；load-use 需停一个周期；编译器调整指令顺序 |
| 控制冒险 | 转移指令使下一条取指不确定 | 暂停等待；静态/动态分支预测；延迟转移 |

- 数据冒险示例：ADD 的结果第 5 周期才写回 R1，而紧接的 SUB 第 3 周期就要读 R1 \(\twoheadrightarrow\) 必须停顿或转发。
- load-use 冒险：LOAD 后紧跟使用其结果的指令，转发来不及，需停顿一个周期。
- 分支预测：静态总是猜“不跳转”，动态根据历史记录预测。

#### **5.7.2 直观理解**

冒险就是流水线里的“前后工序互相等”：没料（数据）、抢工具（结构）、不知道下一步（控制）。

#### **5.7.3 典型应用**

现代 CPU 大量使用数据转发与分支预测，编译器也按流水线重排指令。

#### **5.7.4 易错提醒**

按序流水线主要是 RAW（写后读）数据冒险；WAR/WAW 是乱序执行才需要关注。

---

### 5.8 **并行技术：超标量、超流水线、VLIW 与 Flynn 分类**

#### **5.8.1 定义/要点**

- 超标量：设置多条流水线，每个周期可发射多条指令（指令级并行）。
- 超流水线：把流水线分得更细、段数更多，提高主频。
- 超长指令字 VLIW：由编译器把可并行的操作打包成一条长指令，硬件简单。
- Flynn 分类：SISD（单指令流单数据流，普通单核）、SIMD（单指令多数据流，向量处理器/GPU，数据级并行）、MISD（几乎没有实用）、MIMD（多指令多数据流，多核/多处理器，线程级并行，共享存储）。

#### **5.8.2 直观理解**

超标量像“多条流水线同时开”，SIMD 像“一台机器同时给多个学生发同一张卷子”，MIMD 像“多个老师各带各的班”。

#### **5.8.3 典型应用**

GPU 是典型 SIMD（数据并行）；多核 CPU 是 MIMD（线程并行）。

#### **5.8.4 易错提醒**

SIMD 利用的是数据级并行，MIMD 利用的是线程级并行，二者不要混记。

---


## 六、总线

---

### 6.1 **总线概述**

#### **6.1.1 定义/要点**

- 总线：连接多个部件、各部件共享的传输线路。
- 任一时刻只能有一个部件发送数据，但可以多个部件同时接收。
- 按连接部件分：片内总线（芯片内部）、系统总线（CPU/主存/IO 接口之间）、通信总线（计算机之间）。

#### **6.1.2 直观理解**

总线像“共用一条走廊”——同一时刻只能有一个人往走廊里喊话，但所有人都能听到。

#### **6.1.3 典型应用**

CPU 与主存、IO 接口之间通过系统总线互连。

#### **6.1.4 易错提醒**

“发送唯一、接收多方”是总线的基本规则；否则会发生总线冲突。

---

### 6.2 **系统总线分类**

#### **6.2.1 定义/要点**

| 总线 | 方向 | 位数含义 | 典型功能 |
|------|------|----------|----------|
| 数据总线 | 双向 | 宽度 = 一次可传的位数 | 传数据/指令 |
| 地址总线 | 单向，由 CPU 发出 | 根数 N \(\rightarrow\) 可寻址 \(2^N\) 个存储单元 | 给出访问地址 |
| 控制总线 | 双向/单向混合 | — | 传送控制信号与状态 |

- 地址总线位数决定可访问的地址空间大小：N 根地址线可访问 \(2^N\) 个存储单元。
- 数据总线宽度一般与 MDR 位数对应；地址总线宽度一般与 MAR 位数对应。

#### **6.2.2 直观理解**

地址总线像“门牌号位数”——门牌号位数越多，能编的门牌越多；数据总线像“门洞宽度”——越宽一次搬的东西越多。

#### **6.2.3 典型应用（例题）**

32 根地址线 \(\rightarrow\) 可寻址 \(2^{32} = 4G\) 个存储单元；8 字节数据总线一次可传 64 位。

#### **6.2.4 易错提醒**

地址总线是“单向、CPU 发出”；数据总线“双向”。

---

### 6.3 **总线结构与性能指标**

#### **6.3.1 定义/要点**

- 单总线：所有部件挂在一条总线上，简单但易成瓶颈。
- 双总线：主存总线 \(+\) IO 总线，高速低速分开，效率更高。
- 三总线：如主存总线 \(+\) IO 总线 \(+\) DMA 总线。
- 现代 PC：以桥接芯片为核心的层次化总线结构（如 PCIe）。
- 总线带宽 \(=\) 总线宽度（字节） \(\times\) 工作频率；若每几个时钟周期传一次，还要除以周期数。

#### **6.3.2 直观理解**

单总线像“一条街上的早市”什么都挤在一起，多总线像“高速路和辅路分开”。

#### **6.3.3 典型应用（例题）**

总线宽 32 位 \(= 4\) 字节，时钟 100MHz，每 2 个时钟周期传一次：带宽 \(= 4\times 100\mathrm{M}\div 2 = 200\mathrm{MB/s}\)；若上升沿下降沿各传一次则再乘 2。

#### **6.3.4 易错提醒**

算带宽先看一个总线周期含几个时钟周期、每个总线周期传多少数据；位宽要换成字节。

---

### 6.4 **总线仲裁**

#### **6.4.1 定义/要点**

| 方式 | 控制线数量 | 优先级 | 特点 |
|------|-----------|--------|------|
| 链式查询 | 3 根（BS、BR、BG） | 固定：离控制器越近越优先 | 电路简单，但链上某处故障影响后面设备，对故障敏感 |
| 计数器定时查询 | \(\lceil \log_2 N \rceil\) 根设备地址线 + 2 根 | 灵活可编程 | 设备地址可由计数器设定，优先级可变 |
| 独立请求 | \(2N+1\) 根 | 灵活 | 响应最快，但控制线多、电路复杂 |

总线仲裁解决“多个设备同时申请使用总线”的冲突，常用集中式仲裁。

#### **6.4.2 直观理解**

链式查询像“班长按座位顺序问谁要用”，独立请求像“每人直接举手，班长马上看到”。

#### **6.4.3 典型应用**

PCI 总线采用独立请求仲裁；早期单总线常考链式查询。

#### **6.4.4 易错提醒**

链式查询优先级固定且对故障敏感；计数器定时查询设备地址线根数 \(= \lceil \log_2 N \rceil\)（向上取整）。

---

### 6.5 **总线定时与通信方式**

#### **6.5.1 定义/要点**

- 同步定时：统一时钟，简单快速，但要求设备速度相近。
- 异步定时：靠握手信号协调，分不互锁、半互锁、全互锁；全互锁最可靠。
- 半同步通信：同步为主 \(+\) 异步应答（如 PCI）。
- 分离式通信：设备分时占用总线，利用率高。

#### **6.5.2 直观理解**

同步像“统一按铃声上下课”，异步像“双方举手确认后再继续”，全互锁是“你来我往都确认”。

#### **6.5.3 典型应用**

早期 ISA 同步总线、PCI 半同步、串口 UART 异步握手。

#### **6.5.4 易错提醒**

同步定时不能适应速度差异大的设备；异步定时的可靠性排序：全互锁 \(>\) 半互锁 \(>\) 不互锁。

---

## 七、输入输出系统

---

### 7.1 **IO 接口与 IO 端口**

#### **7.1.1 定义/要点**

- IO 设备种类繁多、速度差异大，需要 IO 接口（IO 控制器）做桥梁：数据缓冲、速度与格式转换、串行并行转换、传送控制命令和状态信息。
- 接口中可被 CPU 直接访问的寄存器叫端口：数据端口、状态端口、控制端口。
- 端口编址：统一编址（端口与主存共用地址空间，用普通访存指令访问）；独立编址（专用 IO 指令，如 x86 的 IN/OUT）。

#### **7.1.2 直观理解**

IO 接口像“翻译 + 缓冲带”：一边是 CPU 的快节奏，一边是外设的慢节奏，接口负责协调。

#### **7.1.3 典型应用（代码示例）**

```
IN AL, 60H ；x86 从端口 60H 读一个字节到 AL
OUT 60H, AL ；把 AL 内容写到端口 60H
```


#### **7.1.4 易错提醒**

统一编址可用访存指令但占用主存地址空间；独立编址需专用 IO 指令，不影响主存空间。

### 7.2 **CPU 与外设交换数据的四种方式**

#### **7.2.1 定义/要点**

- 程序查询方式：CPU 不断查询外设状态，直到就绪再传送。
- 程序中断方式：外设就绪时向 CPU 发中断请求，CPU 响应后执行服务程序传送。
- DMA 方式：DMA 控制器接管总线，在外设与主存之间直接传整块数据，传送期间 CPU 不参与。
- 通道方式：由通道处理器执行通道程序，控制多台外设与主存交换数据。

#### **7.2.2 直观理解**

查询像“每隔几秒打电话问货到没”，中断像“货到了对方打电话通知你”，DMA 像“直接让快递员自己搬货上楼，你只签个字”。

#### **7.2.3 典型应用**

键盘用中断，磁盘用 DMA，大型机用通道。

#### **7.2.4 易错提醒**

程序查询 CPU 空等效率最低；中断每传一字都要中断一次，对高速块设备 CPU 会被频繁打断。

### 7.3 **程序中断：响应条件与处理流程**

#### **7.3.1 定义/要点**

- CPU 响应中断的三个条件：
  - ① 有中断请求；
  - ② CPU 允许中断（中断允许触发器 \(= 1\)，处于开中断）；
  - ③ 一条指令执行完毕（在指令周期结束时检查）。
- 中断隐指令（硬件自动完成，不是真正指令）：关中断、保存断点（PC 入栈）、引出中断服务程序（入口地址送 PC）。
- 中断服务程序（软件完成）：保护现场（寄存器压栈） \(\twoheadrightarrow\) 执行中断服务 \(\twoheadrightarrow\) 恢复现场 \(\twoheadrightarrow\) 开中断 \(\twoheadrightarrow\) 中断返回。
- 考点：保存断点、关中断是硬件做的；保护现场、恢复现场是软件（中断服务程序）做的。
- 多重中断：在保护现场之后、执行中断服务之前开中断，允许更高优先级打断。

#### **7.3.2 直观理解**

中断像“正在写作业被电话打断”——先记住写到哪（保存断点），接完电话再继续（恢复现场）。

#### **7.3.3 典型应用**

键盘敲键产生中断，CPU 执行键盘服务程序读取按键码。

#### **7.3.4 易错提醒**

“关中断 \(+\) 保存断点”由硬件隐指令完成；“保护/恢复现场”由软件完成；开中断必须在保护现场之后、执行服务之前。

---

### 7.4 **中断判优与多重中断屏蔽字**

#### **7.4.1 定义/要点**

- 中断判优一般顺序：硬件故障 \(>\) 软件中断 \(>\) 非屏蔽中断 \(>\) 可屏蔽中断；可屏蔽中断里 DMA 请求高于 IO 中断、高速设备高于低速设备。
- 响应优先级由硬件排队电路决定，固定不变；处理优先级可通过屏蔽字改变。
- 每个中断源对应一个屏蔽字，某位为 1 表示屏蔽对应中断源。

#### **7.4.2 直观理解**

屏蔽字像“请勿打扰”牌子——某位是 1，相当于挡住那个中断不接待。

#### **7.4.3 典型应用（例题）**

\(\mathrm{A > B > C > D}\) 的响应优先级，改为 A D C B 的处理优先级：处理 A 时屏蔽字 1111（屏蔽所有）；处理 D 时 1011（只让 A 打断）；处理 C 时 0111（A、D 可打断）；处理 B 时 0100（谁都不可打断）。

#### **7.4.4 易错提醒**

响应优先级固定（硬件排队），处理优先级可调（屏蔽字）；写屏蔽字前先明确要允许哪些中断打断当前处理。

### 7.5 **DMA 方式**

#### **7.5.1 定义/要点**

- DMA 在外设与主存之间开辟直接数据通路，由 DMA 控制器接管总线传整块数据，传送期间 CPU 不参与。
- DMA 控制器组成：主存地址计数器、传送长度计数器、数据缓冲寄存器、DMA 请求触发器、控制与中断机构。
- 传送三阶段：预处理（CPU 设置主存起始地址、传送字数、方向，启动设备） \(\twoheadrightarrow\) 数据传送（DMA 硬件完成） \(\twoheadrightarrow\) 后处理（DMA 发中断请求，CPU 校验收尾）。

#### **7.5.2 直观理解**

DMA 像“快递员自己搬货上楼”，CPU 只告诉地址和数量就继续干自己的事，搬完再打个电话。

#### **7.5.3 典型应用**

磁盘、SSD 与主存之间的数据块传送。

#### **7.5.4 典型应用（考点）**

DMA 与 CPU 同时请求访存时 DMA 优先——IO 数据不及时取走会丢失；CPU 每个机器周期结束都可响应 DMA 请求，而中断请求只在指令周期结束才响应。

#### **7.5.5 DMA 与 CPU 访存冲突三种处理**

- 停止 CPU 访存；
- 周期挪用（周期窃取）；
- DMA 与 CPU 交替访存（一个周期劈成两半）。

#### **7.5.6 易错提醒**

DMA 只能传数据、不能处理异常事件；中断靠程序切换适合低速设备但每字都要中断，DMA 靠硬件传整块适合高速设备。

### 7.6 **中断与 DMA 对比（经典计算题）**

#### **7.6.1 定义/要点**

| 对比项 | 程序中断 | DMA |
|--------|----------|-----|
| 实现 | 程序切换，保护/恢复现场 | 硬件传送，不需切换程序 |
| 传送单位 | 字/字节 | 数据块 |
| 适合设备 | 低速设备，可处理异常事件 | 高速成块设备，只传数据 |
| CPU 开销 | 每次传送都要中断 + 服务程序 | 仅预处理与后处理 |

#### **7.6.2 典型应用（例题）**

CPU 主频 500MHz，外设数据传输率 2MB/s。中断方式每次传 4 字节、每次开销 500 个时钟周期：每秒中断 50 万次，占用 2.5 亿个时钟周期，占 5 亿的 \(50\%\)。DMA 方式每次传 4KB、预处理 \(+\) 后处理共 500 个周期：每秒约 500 次，仅占约 25 万个时钟周期，约占 \(0.05\%\)。差距约 1000 倍。

#### **7.6.3 直观理解**

同样是 2MB/s 的数据，中断像“每送 4 字节就停下来开一次会”，DMA 像“一卡车一次拉走 4KB，只在装车卸车时开会”。

#### **7.6.4 易错提醒**

先算“每秒几次”，再乘每次开销折算成时钟周期占比；别把字节数与字长单位搞混。

### 7.7 **外部设备：磁盘、显示器、RAID 与 SSD**

#### **7.7.1 定义/要点**

- 磁盘平均存取时间 = 平均寻道时间 + 平均旋转延迟 + 传输时间；平均旋转延迟 = 转半圈的时间。
- 显示器：显存容量 = 分辨率 × 每像素颜色位数；刷新率决定显存带宽需求。
- RAID0：数据分条，速度快、无冗余；RAID1：镜像，双份存储；RAID5：校验分布，坏一块盘可恢复。
- SSD 用闪存，以页读写、以块擦除，写前必须先擦除，需要磨损均衡防止某些块过早损坏。

#### **7.7.2 直观理解**

磁盘寻道和旋转是“大头”，传输反而快；RAID 像“多个人分着背行李，还留备份以防丢”。

#### **7.7.3 典型应用（例题）**

转速 6000 转/分 \(\twoheadrightarrow\) 转一圈 10ms，平均旋转延迟 5ms；平均寻道 6ms、每盘道 500 扇区 \(\twoheadrightarrow\) 读一个扇区传输 \(10\div 500 = 0.02\mathrm{ms}\)；加控制器延迟 0.2ms，总计约 11.22ms。\(1920\times 1080\times 24\) 位真彩色 \(\twoheadrightarrow\) 显存约 5.93MB；60Hz 刷新 \(\twoheadrightarrow\) 显存带宽约 373MB/s。

#### **7.7.4 易错提醒**

平均旋转延迟是“半圈”不是一圈；RAID0 没有冗余，RAID1 冗余但容量减半，RAID5 折中。

### 8.1 **贯穿全课的三大思想**

#### **8.1.1 定义/要点**

- 层次化：用小而快的存储 + 大而慢的存储，换来又快又大的整体效果（Cache、虚拟存储、存储层次）。
- 局部性：时间局部性 + 空间局部性，Cache、TLB 都建立在其上。
- 并行：从先行进位、交叉存储到流水线、超标量、多核，让更多事情同时发生。

#### **8.1.2 直观理解**

层次化解决“快与大的矛盾”，局部性决定“该把什么放得快”，并行决定“怎么同时干更多活”。

#### **8.1.3 易错提醒**

层次化是“结构”，局部性是“依据”，并行是“手段”，三者服务于不同问题。

### 8.2 **高频考点速记清单**

#### **8.2.1 定义/要点**

| 考点 | 关键结论 |
|------|----------|
| 冯诺依曼 | 五大部件 + 存储程序；MAR 位数决定寻址空间，MDR 位数等于存储字长 |
| 性能指标 | CPI、MIPS、FLOPS 公式；执行时间 = 指令条数 × CPI × 时钟周期 |
| 补码 | 0 唯一；范围 \(-2^{n-1} \sim 2^{n-1}-1\)；减法变加法 |
| IEEE754 | float 偏置 127、隐藏位 1.M；阶码全 0 非规格化、全 1 无穷/NaN |
| 存储器扩展 | 2K×4 → 8K×8 需 8 片；片内地址线 = log2 字数 |
| Cache | 直接/全相联/组相联；LRU 计数器 log2 路数；总容量含有效/脏/标记位 |
| 寻址方式 | 立即/寄存器 0 次访存，直接/寄存器间接/变址/基址/相对 1 次，间接 2 次 |
| 流水线 | 总时间 \((K+N-1)\Delta t\)；加速比、效率公式；\(N\to\infty\) 加速比趋近 K、CPI→1 |
| 中断 vs DMA | 硬件做关中断/保存断点；软件做保护/恢复现场；DMA 优先于 CPU 访存 |
