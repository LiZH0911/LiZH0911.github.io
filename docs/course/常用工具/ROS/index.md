# ROS


## 一、ROS 入门

### 1.1 **什么是 ROS？**

ROS（Robot Operating System，机器人操作系统）并不是传统意义上的操作系统（如 Windows、Linux），
而是一个用于机器人软件开发的元操作系统（meta-operating system），
或者说是一个分布式通信中间件 + 工具链 + 软件生态。
它运行在 Linux（主流）、Windows、macOS 等系统之上，为机器人应用提供通信、调度、抽象和工具支持。

### 1.2 **ROS 解决的核心问题**

机器人软件通常涉及大量传感器（激光雷达、摄像头、IMU）、执行器（电机、舵机）、算法模块（SLAM、路径规划、感知）以及人机交互。
如果每个模块都自己写通信、自己管理进程，会非常混乱。

ROS 主要提供：

* **分布式通信机制**：让不同进程（甚至不同机器）之间方便地交换数据。
* **硬件抽象**：统一接口访问传感器和执行器。
* **软件复用**：大量开源功能包（导航、建图、机械臂控制等）可直接使用。
* **工具与可视化**：调试、录制、回放、可视化工具。
* **包管理**：组织代码、依赖和编译。

### 1.3 **ROS 的两个主要版本**

- ROS 1：2007 年起源于斯坦福，长期主流，基于 TCP/UDP 自定义通信，中心节点 Master。官方支持已于 2025 年 5 月终止（Noetic 是最后一个版本）。
- ROS 2：2017 年正式推出，基于 DDS（数据分发服务）通信，去中心化，支持实时性、多机器人、嵌入式和安全加密，是当前和未来的主力。

目前新项目基本都建议直接使用 ROS 2（如 Humble、Jazzy 等 LTS 版本）。

### 1.4 **ROS 的核心概念**

- **节点**（Node）：一个节点就是一个独立进程，负责一项具体功能，比如读取摄像头、做 SLAM、控制底盘。节点之间通过通信机制交互。
- **话题**（Topic）：发布/订阅
- **服务**（Service）：请求/响应
- **动作**（Action）：ROS 2 中动作基于服务 + 话题实现
- **参数**（Parameter）：节点的配置项，如速度上限、相机分辨率。ROS 2 中参数与节点生命周期绑定更紧密。
- **消息**（Message）：通信的数据结构，用 `.msg` 定义
- **坐标系与 TF**：`tf2` 库管理机器人各部件之间的坐标变换（如底盘→雷达→相机），是导航和机械臂的基础。
- **生命周期与执行器**（ROS 2）：节点有状态（未配置、激活、停用等），便于系统启动和容错管理。Executor 负责调度回调，支持单线程/多线程。

### 1.5 **ROS 常用工具和指令**

常用工具：

| 工具 | 作用 |
|------|------|
| `rviz2` | 3D 可视化：点云、图像、TF、路径、模型 |
| `rqt` | 图形化插件框架：话题监控、参数编辑、 plotting |
| `ros2 bag` | 录制/回放话题数据 |
| `ros2 topic/service/node` | 命令行查看和调试 |
| `Gazebo` / `Ignition` | 物理仿真 |
| `Nav2` | ROS 2 导航栈 |
| `MoveIt 2` | 机械臂运动规划 |
| `ros2_control` | 实时控制器框架 |
| `colcon` | 编译构建工具 |
| `rosdep` | 依赖安装 |

常用指令：

- **ros2 run**：运行节点
- **ros2 topic**：发布/订阅话题
- **ros2 service**：请求/响应服务
- **ros2 action**：动作
- **ros2 param**：参数
- **ros2 node**：节点
- **ros2 pkg**：包
- **ros2 launch**：启动

### 1.6 **典型开发流程**

1. 创建工作空间（workspace）和功能包（package）。
2. 用 C++ 或 Python 编写节点。
3. 定义消息/服务/动作接口。
4. 用 `colcon build` 编译。
5. 用 `ros2 launch` 启动多个节点。
6. 用 `rviz2`、`rqt`、`ros2 bag` 调试。
7. 在 Gazebo 或真机上验证。
